# Open Questions
<!-- status: final -->

Anything that would otherwise become "we'll figure it out later." Every entry
needs an owner and a decide-by date. This register is what stops the exit
criteria being silently dodged.

Rules:
- A `verdict: unknown` on a deep project belongs here.
- An unresolved conflict between two projects' designs belongs here.
- Closing an entry means linking the ADR or document that resolved it.

## Status key

`open` · `investigating` · `resolved` · `deferred` (with a reason and a revisit date)

| OQ-031 | Does HumanLayer's daemon reconcile approvals on restart — can a tool call whose approval was decided while the daemon was down still proceed? | HumanLayer teardown | | Phase 5 | **resolved** | **Yes, and it is a named abstraction.** `session.ApprovalReconciler` is documented as an "interface for reconciling approvals after session restart", with `ReconcileApprovalsForSession(ctx, runID)` called from three sites in `session/manager.go` (:522, :1849, :2067). | OQ-040 | Is Agent Control's `namespace_key` enforced in the schema, or only a filter parameter? | Agent Control teardown | | Phase 5 | **resolved** | **Enforced, and more strongly than anywhere else in the study.** `namespace_key` is in the composite **primary** key *and* in composite **foreign** keys on the association tables, with the intent stated in a comment: "Composite FKs enforce same-namespace references on both sides" (`server/src/agent_control_server/models.py:41-80`). Omnigent and ADK prevent unscoped *reads*; this also prevents cross-namespace *writes*, so binding a policy in namespace A to a control in namespace B is a constraint violation. For a policy system that is the more dangerous case. **I had recorded it as a filter field after reading only the API models** — third time in this study that the schema overturned an inference from an API surface. |
| OQ-041 | Does Agent Control's `observe` mode support running a candidate control against live traffic alongside an enforced one (true A/B shadow), or only non-blocking evaluation? | Agent Control teardown | | Phase 5 | **resolved** | **True A/B shadow.** All controls bound to a target evaluate **concurrently** under a semaphore, each recording its own `ControlExecutionEvent`, and only `deny`/`steer` affect the outcome (`engine/src/agent_control_engine/core.py:662-780`). So a candidate control runs on the same live traffic as the enforced ones without changing behaviour. **One caveat carried into ADR-0013 amendment 2**: a `deny_found` event cancels remaining evaluations, so observe controls may record no verdict for *denied* traffic — biasing the shadow sample away from exactly the cases a candidate policy most needs comparing on. Our observe evaluations must be exempt from deny-triggered cancellation, accepting the latency cost. |
